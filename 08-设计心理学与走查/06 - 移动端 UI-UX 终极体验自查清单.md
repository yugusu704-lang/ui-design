# 移动端 UI-UX 终极体验自查清单 (Mobile Audit Checklist)

> 整理自全球经典前端与体验走查开源项目 `thedaviddias/Front-End-Checklist` 与各大厂上线质检规范。
> 在任何移动端产品发布、切图交付或 Vibe Coding 原型交付前，执行以下逐项走查。

---

## 🖐️ 维度一：触觉与物理操作走查 (Touch & Physics)

- [ ] **触控靶心达标**：所有可点击图标、标签按钮的热区是否达到最小 `44×44pt` (iOS) 或 `48×48dp` (Android)？
- [ ] **边缘误触与间距**：相反高危按钮（如“清空”与“保存”）之间是否有至少 `12px` 的安全防误触间距？
- [ ] **点击瞬时反馈**：所有按钮按下时是否有微下凹（`:active scale(0.96)`）或状态颜色变暗，确保反馈在 `100ms` 内？
- [ ] **原生返回手势支持**：是否保留了 iOS 屏幕左边缘右滑返回手势，且滑动中无白屏闪烁？
- [ ] **拇指热区适配**：单手操作最频繁的核心行动点（CTA），是否位于屏幕中下段而不是左上角？

---

## ⌨️ 维度二：键盘与表单输入走查 (Keyboard & Inputs)

- [ ] **软键盘遮挡避让**：输入框被聚焦时，页面是否自动平滑上滚，确保当前输入框与提交按钮不被弹出的软键盘挡住？
- [ ] **专用键盘类型匹配**：
  - 手机号/纯数字：是否配置了 `inputmode="numeric"` 或 `type="tel"`？
  - 邮箱：是否配置了 `type="email"`（自动唤出带有 `@` 和 `.com` 的键盘）？
- [ ] **一键清空与密码可见**：长文本输入框是否配备右侧微小的 `(x)` 清空按钮？密码框是否带眼睛图标切换明密文？
- [ ] **自动组块分段**：银行卡与手机号在输入时是否自动插入易于核对的空格？

---

## 🌓 维度三：色彩对比度与暗黑模式 (Contrast & Dark Mode)

- [ ] **强光与弱光易读性**：小号辅助文字与背景色的对比度是否通过 WCAG AA 级（至少 `4.5:1`）？
- [ ] **暗黑模式无纯黑眩光**：Dark Mode 下是否使用 `#0B0D0E` 或 `#121212` 替换刺眼的 `#000000`？文字是否使用柔和白 `#F8FAFC`？
- [ ] **半透明毛玻璃抗冲刷**：模糊毛玻璃容器背后经过高饱和图片或文字滚动时，容器内前景文字是否依然清晰可读？

---

## ⚡ 维度四：弱网、加载与异常走查 (Edge Cases & States)

- [ ] **骨架屏流转**：首次首屏加载是否采用与卡片比例完全一致的骨架屏（Skeleton），杜绝空白或死板大转圈？
- [ ] **断网与空状态表达**：
  - 遇到列表无数据时，是否配备了友好的插画与引导性文案（如“暂无订单，去逛逛吧”+ 按钮）？
  - 遇到接口报错时，是否提供了一键“重新加载 (Retry)”按钮？
- [ ] **防重复点击提交**：在用户点击“支付/提交”后，按钮是否立即置灰并转为 Loading 动画，防止由于网络延迟导致的双击重复扣款？
